## 项目是什么

项目是一个**文件夹**，你可以像复制、移动或备份其他文件夹一样处理它：

- `project.json`：你的整个游戏，放在一个文件里（JSON 格式的文本，缩进为 2 个空格）。
- `assets`：你导入的图片。
- `backups`：`project.json` 的较早版本；`backups/deleted-assets` 里是你删除的图片。

每次保存时，NovelWorks 都会安全地写入文件（先写入临时文件，再重命名），所以保存时即使崩溃也不会损坏它。

## 格式版本

`project.json` 有一个**格式版本**。这个版本的 NovelWorks 写出的是格式 **17**。每当格式发生变化，NovelWorks 都会增加一个自动升级，所以每个较旧的项目仍然可以打开。其中的一些变化：

| 格式 | 新增了什么 |
|---|---|
| 2 | 对话框选项（九宫格边角、文字颜色、所有姓名使用同一种颜色）和拼写语言。 |
| 3、4 | 作者笔记、剧情地图上的位置、场景摘要和写作状态。 |
| 5 | 探索片段（区域和道具）。 |
| 6 | 物品和可选功能。 |
| 7 | 角色的自由摆放。 |
| 8 | 地图功能。 |
| 9 | 游戏标识符（用于玩家的存档），以及保存和读取画面的外观。 |
| 10、12、13 | 历史记录、快捷菜单和选项画面的外观。 |
| 11 | 单独空间中的地图。 |
| 14 | 片头图片和内容提示。 |
| 15 | 角色留在舞台上：一个片段只记录它所更改的内容。 |
| 16 | 带有多个情况的“如果…”。 |
| 17 | 只有在某个条件成立时才出现的选择选项。 |

## 打开较旧的项目

- NovelWorks 只在**内存中**升级项目。在把项目交给编辑器之前，它会在 `backups` 里保存一份原始 `project.json` 的**完全相同的副本**，名字类似 `project-2026-11-07_17-15-04-migration.json`，并检查副本是否一致。
- 如果无法制作副本，项目就**不会打开**，也不会有任何改动。
- 一个提示条会告诉你副本在哪里（用 {ui.store.showCopy}），并说明你必须保存才能保留升级。此时项目算作未保存。
- 不保存就重新打开，会重复使用同一份副本。这些“{tx.restoreBackupDialog.beforeUpgrade}”副本永远不会被删除。
- 你可以用 **{ui.native.menu.file} → 从备份恢复…** 回到原始版本。

玩家为你游戏做的存档仍然可以读取：存档通过身份来指向场景和片段。

## 打开较新的项目

由**较新**版本的 NovelWorks 保存的项目无法打开：NovelWorks 会这样告诉你，并请你更新。不会有任何改动。

如果文件夹里没有 `project.json`，或者文件已损坏（不是有效的 JSON），NovelWorks 会告诉你，并且不会打开它。

## 备份

见[保存、备份和撤销](/novelworks-docs/zh-cn/getting-started/saving-and-undo/)：每次手动保存前都会备份，自动保存最多每 15 分钟备份一次，保留最新的 20 份，再加上最近 7 天里每天最新的一份。

## 手动编辑文件

你可以用文本编辑器打开 `project.json`，但是当 NovelWorks 打开着这个项目时不要编辑它，并且先保留一份副本。NovelWorks 会拒绝它读不懂的文件，而不是去猜。

## 演示版和完整版

两个版本使用完全相同的格式。见[免费演示版](/novelworks-docs/zh-cn/getting-started/demo-edition/)。
