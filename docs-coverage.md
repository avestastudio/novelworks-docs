## Les variables : Score et Fait, « Si… », « Faire retenir quelque chose au jeu » (problème 2, phase A)
- [ ] **Vocabulaire (décidé après le test avec le frère)** : on garde le mot **« variable »** partout (variable / variable / variable / variável / 变量 / переменная / 変数), Mode Script compris. « Mémoire » (Memory…) a été essayé et abandonné ; un test de vocabulaire garde ce mot hors des catalogues. Ce qui est nouveau : deux **sortes** de variables, **Score** (un nombre qui monte et descend ; EN Score / FR Score / ES Puntuación / PT Pontuação / ZH 分数 / RU Счёт / JA スコア) et **Fait** (quelque chose s'est passé, oui ou non ; Fact / Fait / Hecho / Fato / 事实 / Факт / できごと) ; et le moment « Condition » devient **« Si… »** (If… / Si… / Si… / Se… / 如果… / Если… / もし…). ## « Si… » à plusieurs cas (phase B, étape 1 : le format 16)
- [x] Un moment « Si… » peut maintenant contenir **plusieurs cas**, chacun avec **une ou plusieurs conditions** reliées par « et » (toutes doivent être vraies) ou « ou » (une seule suffit), et une scène où aller. Les cas sont vérifiés **dans l'ordre** : le premier qui est vrai gagne. Si aucun n'est vrai : « sinon » (ou le jeu continue). — **branching/conditions** (D3)
- [ ] Les projets existants s'ouvrent comme avant : l'ancien « si X alors A sinon B » devient un seul cas + « sinon B » ; le jeu va exactement aux mêmes scènes (vérifié sur tous les projets réels). Une copie de sécurité est faite automatiquement avant la conversion (format 15 → 16).
- [x] Un cas qui vérifie une variable ou un objet disparu arrête la vérification : le jeu continue avec le moment suivant (comme avant pour un test cassé). — **branching/conditions** (D3)
- [ ] Étape 1 : seul le moteur et le format changent ; l'éditeur et le Mode Script montrent encore un seul cas (étapes suivantes).

## Mode Script : « et », « ou », « sinon si » (phase B, étape 2)
- [x] Plusieurs conditions dans un cas : `si Affection >= 3 et objet Clé -> Parc` (toutes) ou `si Vu = vrai ou Affection > 8 -> Gare` (une seule). Dans une même ligne, on ne mélange pas « et » et « ou » : le Mode Script prévient et ne garde que le premier. — **writing/script-mode-conditions** (D2)
- [x] Plusieurs cas, une ligne chacun, le premier qui est vrai gagne : `si Affection >= 5 -> Parc` / `sinon si Affection >= 2 -> Gare` / `sinon -> Fin`. — **writing/script-mode-conditions** (D2)
- [ ] Les mots existent dans les 7 langues (et / ou : et·ou, and·or, y·o, e·ou, 并且·或者, и·или, かつ·または) ; les mots de toutes les langues sont compris en même temps.
- [ ] Les anciens scripts se lisent et se réécrivent exactement pareil : `si X -> A, sinon -> B` reste sur une seule ligne tant qu'il n'y a qu'un cas. Les noms qui contiennent « et » (ex. « Rock et Roll ») restent compris.
- [x] Une ligne « sinon… » qui ne continue pas une condition reste du texte normal (ex. « Sinon, il pleuvait. »). — **writing/script-mode-conditions** (D2)

## Éditeur : un « Si… » à plusieurs cas (phase B, étape 3)

- [x] Un seul cas avec une seule condition : l'écran reste identique à avant. — **branching/conditions** (D3)

## Phase C, étape 1 : « jusqu'à +5 » (ce que tes choix peuvent donner)
- [x] Sous chaque test sur un **Score**, dans un « Si… » : « Tes choix peuvent ajouter jusqu'à +5 à Affection en tout. » (ou « de 0 à 5 » s'il y a aussi des baisses), puis « ✓ Cela peut arriver. » ou, en orange, « ⚠ Ce ne sera jamais vrai : Affection reste entre 0 et 5. ». - [x] Le calcul additionne, pour chaque choix, la meilleure (et la pire) option, et chaque zone une fois. - [x] Un Fait (oui/non) n'a pas de fourchette ; « Rien ne change encore Affection » s'affiche quand aucun choix ne la modifie. — **branching/reach** (D3)

## Phase C, étape 3 : une option de choix qui dépend d'une condition (format 17)
- [x] Dans un choix, chaque option a un bouton **« N'afficher cette option que si… »** : mêmes conditions que le « Si… » (une ou plusieurs, « et » / « ou »). Quand la condition est fausse, on choisit : **« Cacher l'option »** ou **« L'afficher grisée »** (elle reste visible mais on ne peut pas la choisir). « Toujours disponible » la remet comme avant. — **branching/choices** (D3)
- [x] Dans le jeu : l'option cachée n'apparaît pas (les touches 1 à 6 comptent les boutons visibles) ; l'option grisée ne répond pas au clic. **Les joueurs ne sont jamais bloqués** : si aucune option ne pouvait être choisie, elles s'affichent toutes. — **branching/choices** (D3)

- [x] Les variables/objets utilisés par une option apparaissent dans leurs listes « Vérifiée par » ; changer le type d'un Score en Fait corrige aussi ces conditions ; une option qui vérifie quelque chose de supprimé est signalée dans les problèmes du moment. — **branching/variables** (D3)
